# Spec 标准模板

> 契约模板：本项目所有 spec 文档均遵循此章节结构。偏离模板的 spec 不被视为有效规范。
> 
> 核心理念：同类文档章节骨架一致 → 按固定位置取信息成为可能 → 自动检查脚本可逐字段校验。

---

## 模板结构

```
# [文档标题]

> [一句话摘要：这份 spec 规定什么、受众是谁、上游/下游依赖]

## 1. 术语引用

> 本 spec 使用的核心术语均链接至 [glossary.md](../glossary.md)，不自行重定义。

- [术语1](../glossary.md#术语1) — 本条中的含义
- [术语2](../glossary.md#术语2) — 本条中的含义

## 2. 规范正文

[按实际内容组织。以下为推荐的子结构：]

### 2.1 [子节标题]
[规范内容]

### 2.2 [子节标题]
[规范内容]

## 3. 变更记录

| 日期 | 变更 | 作者 |
|------|------|------|
| YYYY-MM-DD | 初始版本 / 修改说明 | — |
```

---

## 各节填写说明

| 节 | 必填 | 说明 |
|---|---|---|
| 标题 | ✅ | 简洁描述本 spec 规范的内容。不用「说明」「文档」等模糊词 |
| 摘要 | ✅ | 一句话，回答「谁需要读、为什么需要读」 |
| 术语引用 | ✅ | 关键术语必须链接 glossary，不得自行定义。如果无术语依赖，标注「本 spec 无新增术语」 |
| 规范正文 | ✅ | 按实际需要组织子节。表格优先于段落，示例优先于抽象描述 |
| 变更记录 | ✅ | 每次修改必须追加一行，标注改动内容 |

---

## 禁忌

- **禁止**：spec 中自行定义术语（应链接 glossary）
- **禁止**：使用「显然」「应该」「一般」等模糊词替代明确校验标准
- **禁止**：与另一份 spec 描述同一件事但结论不同（违反 SSOT，应单向引用）
- **禁止**：用「详见 xxx 文档」替代必要内容（spec 应自包含关键信息，只能「详见」作为补充）

---

## 示例：用模板重写 design.md Gate 契约

### 原始（有矛盾）
```
| Gate 校验 | F1/F3/F4 FAIL, F2/F5/F6/F7 WARN |
```
→ 与 `concept-spec.md` 矛盾（后者规定 F1-F8 全部 FAIL）

### 用模板重写后
```
| Gate 校验 | 按 `specs/contract/concept-gate.md` 的 F1-F11 规则逐条检查。
  FAIL 级别的字段（F1/F2/F4/F5/F6/F7/F8）缺失或格式错误 → 拒绝入库。
  WARN 级别的字段（F3/F9/F10/F11）缺失 → 可入库但标记 TODO。 |
```
→ 不重复定义规则级别（术语引用），直接指向权威来源（concept-gate.md），矛盾消失。
