大模型有一个现实的短板：训练完、部署上线之后，能力基本就定格了。它每天处理大量真实请求，却很难把这些新经验重新学进去。同一个用户纠正过很多次的偏好，下一次还得重新解释；一个智能体在相同流程里反复失败，这些失败也不会自然变成它的新本事。想让它变强，最直接的办法是拿新数据再训一遍，但对一个千亿、万亿参数的模型来说，全量重训的成本高到根本没法经常做。

*[图片：Image]*

这两天 Mind Lab 开源的 Macaron-V1，正是冲着这个问题来的：冻住庞大的基座，只训练一个很小的附加模块，用强化学习把新经验持续写回参数，让大模型部署之后还能低成本地持续学习。

## 一、Mind Lab 最新开源了 Macaron-V1

做 Macaron-V1 的这支团队，是 Mindverse 旗下研究实验室 Mind Lab，他们不是第一天做智能体。早在 2023 年，团队里的 Andrew 就和现任腾讯集团首席 AI 科学家姚顺雨、普林斯顿的 Karthik Narasimhan 合写过 FireAct，用监督微调把智能体的行为轨迹写进模型参数，是「把经验写进参数」最早的尝试之一。

从 FireAct 到 Macaron-V1,是同一条路走下来的：当年用监督微调一次性写进去,如今换成强化学习持续写回。Mind Lab 沿着这条路把它推到了万亿参数规模。据公开报道,全球能在万亿参数上跑通 LoRA 强化学习的团队屈指可数,他们是其中之一,另一家是前 OpenAI CTO Mira Murati 创立、估值已达一百多亿美元的 Thinking Machines Lab。

这次发布的 Macaron-V1 本身是一个面向个人智能体场景的开源模型，提供两个版本：旗舰版 Venti，7480 亿参数，由一个 744B 的 GLM-5.2 基座加四个 10 亿参数的 LoRA 专家组成，原生支持 200 万 token 上下文；轻量版 Tall，350 亿参数，基于通义千问 3.6，面向本地部署。它更早还有一个预览版 Macaron-V1-Preview，参数是 749B、五个专家，我们后面会提到两代的差别。

## 一、Macaron-V1 核心思路：不重训整个模型，也能让它持续学习

让模型能够持续学习，其实有两条路。

一条不动参数，把经验放进上下文，提示词、记忆、检索、外部技能都算。这条路胜在灵活，但经验存在模型之外，每次用都要重新读一遍，越攒越贵。而且把信息放进上下文，不等于模型真的学会了，能到多强还是卡在模型自己的理解力上。另一条是写进参数，让模型直接内化，面对相似任务时不必每次重读全部历史。Macaron-V1 走的是后者。

全量更新整个模型代价太高，所以具体做法用的是低秩适配，也就是 LoRA：在冻结的基座旁边挂一个参数量很小的可训练模块，小到不足基座的百分之一，训练时只更新它。LoRA 在这条路线里的角色变了。过去它大多被当成省显存、能力打折的廉价替代品，是没资源做全量微调时的妥协。而在这条路线里，它被重新定义成一块承载个性的持久状态，一个会随交互不断演化的记忆。基座提供通用能力，小模块承载某个具体场景下的偏好、技能和工具使用习惯。

把经验变成训练信号这一步，用强化学习来做：模型执行任务、拿到结果，再根据结果好坏去调整小模块的参数。这正好接上了前面 FireAct 的线索。FireAct 当年用的是监督微调，把现成的轨迹一次性写进参数。这条路线把它换成了强化学习，让模型部署之后还能持续地从自己的经验里学，而不是学一次就定格。

Macaron-V1 的架构就是这套思路的直接落地，它叫 Mixture-of-LoRA。在冻结的 GLM-5.2 基座上，它挂了四个各 10 亿参数的 LoRA 专家，各自管理某一环节：

- L0 Chat，负责对话与指令遵循；
- L1 Agent，负责长程、动态、复杂的智能体任务；
- L2 Coding，负责代码理解、软件工程与终端使用；
- L3 UI，负责界面渲染与界面驱动的操作。

新能力以插件式的 LoRA 加入，不动摇已有知识，不同专家还能在同一个基座上组合。

为了亲自试试他们训练出来的模型到底怎么样，我专门在 Claude Code 上配置了 Macaron-V1-Venti，让它做一个 3D 世界生成的任务。我只给了它一句话，十几分钟后就拿到一个双击就能运行的 3D 网页，一个完整的巧克力工厂微缩世界。

我发的就是这一句：

```
「用 Three.js 从零造一个巧克力工厂花园世界：巧克力河、焦糖瀑布、糖果园、传送带、微缩工人，全部程序化生成，不许用外部素材，工人还要有真实的任务队列和路径网络」。
```

这套产出，是在冻结的基座上只训练了一小部分 LoRA 参数拿到的。训练只动了很小一块，效果依然很能打。至于这种“只训一小部分”能省多少、在多大的模型上还成立，正是下一节要讲清的。

## 二、低成本的底气：万亿参数上，算力只要约十分之一

LoRA 本身不是新东西，早期主要用于低成本的监督微调。它能不能扛住强化学习这种更复杂的训练，此前学界一直没有定论。

这个问题的科学结论，最早由 Thinking Machines Lab 在 2025 年的研究给出：只要 LoRA 覆盖到包含前馈层和专家层在内的所有层、且不超过它的容量，它在监督微调和强化学习上都能追平全参数微调，强化学习对秩的要求还很低。这项研究给这条路线打下了科学前提，Mind Lab 再把它推到万亿规模。在他们公开的研究里，团队在万亿参数的稀疏专家模型 Kimi K2（总参约 1.04 万亿、单次激活约 326 亿）上端到端跑通了 LoRA 强化学习，算力开销约为全参数强化学习的十分之一，训练曲线平稳上升，没有出现灾难性发散。他们还发现，把可训练模块压到极低的秩仍能稳定训练，配一套专门的初始化方法就行。

*[图片：Image]*

这条路线的一部分证据还可以外部核对，不用只看官方给的数字：相关训练框架的补丁已经并入几个主流开源训练项目的上游，配套基础设施也以 verl-mint 的名字开源。

对 Macaron-V1 来说，正是这套“在万亿基座上做强化学习也只要十分之一算力”的能力，才让持续更新从一件偶尔为之的重活，变成了可以经常做的常规操作。把成本压到这么低，除了让持续学习变得可行，还打开了另一种可能。

## 三、成本够低，一个基座就能长出一群会协作的小模块

正因为写一次经验的成本被压到这么低，同一个基座上能挂的就不止一个模块。很多个小模块分别学到不同的东西，再让它们协作，整体能力还能往上走一层，这就是群体智能。

*[图片：Image]*

Mind Lab 做过一组对照实验来验证这件事。他们从同一个约 300 亿参数的开源模型（Qwen3-30B）出发，只改数据顺序和训练细节，训出接近两百个小模块，在数学基准 AIME24 上做多数投票。单个模块的准确率是 36.4%，198 个模块一起投票后升到 48.7%，明显高于对同一个模块反复采样所能达到的上限（约 43.3%），也高于基线的 37.3%。这组数字来自受控实验，验证的是"多个模块协作确实能更强"这个规律，并不是 Macaron-V1 本身的成绩。

*[图片：Image]*

Macaron 的模型正是这个思路的产品化。它有两代：预览版 Preview 是 749B 配五个专家，正式版 Venti 是 748B 配四个专家，从五到四不是缩水，而是把 Preview 里和特定场景相关的一个 LoRA 并进了通用的 Agent 专家（两代演进的具体细节以官方口径为准）。支撑这一切的是一套叫 MinT 的基础设施，它把海量小模块的训练、评估、部署、回滚统一管起来，设计目标是能管到百万量级的模块目录。有了这层工程底座，模块规模再大也能有序训练、部署和更新，群体智能才真正落得下来。

*[图片：Image]*

## 写在最后

用 LoRA 承载个性、用强化学习把经验持续写回参数，再靠一套基础设施把海量小模块管起来，Macaron-V1 给"让大模型部署后还能持续学习"提供了一条完整而低成本的实现路径，关键环节都有公开研究和开源代码支撑。

持续学习这个方向本身还有几个公认的难点：模糊反馈下如何稳定地找到可靠的学习信号、不断写入新经验时如何不覆盖旧能力、大量模块的多样性如何真正变成群体层面的能力。这些是整个领域都在求解的问题，而 Macaron-V1 是目前最完整的一次公开作答。

对从业者来说，这条路线有几个点值得借鉴：把适配模块当成可训练的持久状态，而不只是省显存的技巧；与其把一个模型无限往大了做，不如让多个专门的小模块分工再协作；把模块的版本、评估、回滚当成基础设施来管。

据悉近期 DeepSeek 创始人梁文锋也提及，AI 现在不缺品味和直觉，缺的是持续学习的能力，能让模型持续学习才算得上下一代模型。这与 Mind Lab 的判断一致。在他们看来，下一代智能的决定性因素不再是把单一模型越做越大，而是两件事：通过递归自我改进做后训练，让模型持续从经验中学习；以及多智能体协作，让专业化模型在共享基础设施上组合。Macaron-V1，正是迈向这个方向的一个里程碑。
