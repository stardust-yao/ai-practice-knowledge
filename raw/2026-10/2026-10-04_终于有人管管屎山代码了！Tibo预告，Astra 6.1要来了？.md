OpenAI 开发者日才过去了 5 天，Tibo 又来预告下一代模型了。

这一次，他们终于打算管管模型写出来的屎山代码了。

不久前，OpenAI 产品负责人 Tibo Sottiaux 发帖称，未来的模型会更擅长删除和简化代码。

最后还意味深长地说了一句：「真是及时。」

*[图片]*

这似乎不是一句随口预告。

OpenAI 研究员 Rajan Agarwal 随后转发了这条帖子，并表示：「这就是我每天没日没夜在做的事情，很期待看看你们能不能感受到区别。」

Rajan 目前负责 coding post-training，研究重点就是让 coding model 和 Codex 在代码能力之外，也能写出更「有品位」的代码。

*[图片]*

几个小时后，他又把同一条 Tibo 的帖子翻出来，直接向用户征集：「把你见过我们的模型写出来的 sloppy code 发过来。代码质量上，最让你头疼的问题是什么？」

*[图片]*

难道 Astra 6.1 要来了？

Tibo：6.1 coming soon

不久前，《华尔街日报》报道称，OpenAI 原计划在 10 月推出 Astra 6.1，却在内部安全测试后临时叫停。

测试中，这一版本在「权限边界」上表现得不安分，有时会在没有获得用户授权的情况下继续执行操作，对自己究竟做了什么也不够坦诚。

OpenAI 最终决定先不发布，继续解决这些安全和对齐问题。

但就在刚刚，Tibo 在一篇称赞 Astra 6 的帖子下面，留了一条语焉不详的评论：

「6.1 coming soon」

*[图片]*

再结合几小时前预告的代码删减能力，似乎新一代模型的真实水平正在慢慢浮出水面。

codex 下一步，网友说了算？

新模型到底怎么样还不清楚，但看上去 OpenAI 这轮产品更新走的是「群众路线」。

同样在今天，Tibo 连发两条，向网友征集关于 codex 和侧边栏更新的建议。

*[图片]*

*[图片]*

评论里说什么的都有，热评第一是让加上重置按钮（哈哈哈）。

*[图片]*

有人希望 Codex 真正支持 Agent 之间的任务交接：一个 Agent 负责开发，另一个审查，再交给其他 Agent 修复、测试，最后完成交付，全程不需要人手动搬运上下文。

还有人希望直接打通 Codex 和 ChatGPT 的记忆 ——ChatGPT 已经知道自己的项目、习惯和背景，打开 Codex 却又得重新开始。

类似的需求还有不少：统一 Chat、Work 和 Codex 的界面；给大量聊天加入文件夹层级和标签页；让不同电脑上的 Codex Agent 直接协作；甚至允许用户在 Agent 工作到一半时插话、打断，再让它接着做。

还有人提出，希望 Codex 能像一个「项目历史记录员」，自动记住一个长期项目已经推进到了哪里、还有哪些事情没有完成。

当说到侧边栏，有人最关心实用性，希望侧边栏里直接加入 Git 管理，这样就不用为了切分支、看版本状态，再单独打开 IDE。

也有人想把它做成项目仪表盘：放进 token 与 API 成本追踪、功能清单、任务耗时，方便随时查看一个项目到底跑到了哪一步。

还有人希望新的侧边栏承担组织与切换的作用，比如把聊天拆成不同类别，用图标切换，甚至把浏览器也整合进去，避免为了开个网页还得重新起一个 chat。

那么问题来了：如果只能选一个，你最希望 Codex 或下一代模型先更新什么？
