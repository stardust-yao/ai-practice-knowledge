**01**

### 什么是1000 tokens/s？到底有多快？

先科普两个概念：token=词元，是大模型的计量单位，类似菜市场买菜用的“斤”“两”。1000 tokens/s=1000 Tokens Per Second，也叫 1000 TPS，即：每秒生成 1000 个 token。

如果把大模型推理想象成“打字”，TPS 就是它的“打字速度”。数字越高，速度越快。粗略换算，1 个 token ≈ 1~2 个汉字，或者 0.75 个英文单词。**1000 tokens/s≈ 每秒生成约 750 个英文单词，或上千个汉字****。**

对比一下：普通大模型：输出速度 50～130 TPS，像人在朗读；国内顶尖大模型：输出速度 400 TPS，像快语速的播报。我们的版本：输出速度 1000 TPS，是人眼阅读速度的 200 倍。差不多就是你一眨眼，它就“啪”地甩出一整页 A4 纸的文字。

**02**

### 为什么 Xiaomi MiMo 会追求极致的速度？

想象你要从 A 点到 B 点。不着急？坐大巴，一趟装 50 人，两小时到，便宜省心。如果全世界几亿人同时用 AI，本质上就是在坐大巴——大家一起排队，慢慢等结果。

但总有些场景等不了：急救转运、deadline 前交文件、AI Agent 需要毫秒级响应——这时候你需要的是一辆跑车，最快从 A 到 B。

1000 TPS 就是那辆跑车。

打出租肯定比坐大巴贵，所以这不是“谁更好”的问题，而是你的场景需要什么。过去大模型行业只有大巴可选；而现在——当 AI 深度介入工作流，很多人愿意为“快”付溢价，因为慢 3 秒注意力就断了。

更关键的是，AI 正在走向多 Agent 协作：几十个 AI 同时跑，链路上每个环节慢一点，累积就是灾难。单步够快，才是多 Agent 时代的基础设施。

1000 TPS 的意义：让需要极速的人，有跑车可选。

**03**

### 这么快，能用来做什么以前做不到的事？

当速度提升到 1000 tokens/s，改变的不只是体验，而是大模型的能力边界。

过去很多人用 AI 做任务时，最直观的感受就是等待。写代码要等，生成网页要等，多个 Agent 协作更要等如果每一步都等几秒，几十轮下来就是几分钟，甚至几十分钟。

当速度快到 1000 tokens/s，很多原来需要耗时等待的复杂任务，也能“瞬间出结果”。

▍Agent编程：最有体感的变化

假设你让 AI 开发一个小游戏，以前它会一行一行“敲”给你看，然后运行、报错、修改、再运行，像现场观摩程序员加班。现在，很多环节的等待时间极限缩短，整个任务一次成型。原本需要数分钟的多轮协作任务，可以缩短到十多秒甚至更短。

▍多Agent协作真正可用

未来的大模型不会只有一个 AI，而是一群AI同时干活。有的规划，有的查资料，有的写代码，有的检查结果……它们彼此来回上百轮。如果每个都慢，整条链路就会卡死。当单次推理足够快，多 Agent 协作真正具备大规模落地的可能。

▍拓宽实时应用场景

语音对话、实时竞价、辅助医疗等场景，对延迟极其敏感。过去大模型很多时候是能做，但来不及做更高的速度，让大模型开始具备进入实时场景的可能。

比如广告实时竞价，一个广告位从曝光到出价，通常只给你 100 毫秒。过去大模型根本进不去这个战场——太慢就丢单。现在，模型可以实时理解用户需求，再决定出多少钱。

还有客服领域，如果模型慢半拍，对话就变成“你等一下……再等一下”。1000 tokens/s 下，几乎感知不到延迟，语音助手真正像是在“对话”，而不是“等加载”。

未来在对延迟敏感的专业场景中也有更多可能……

**04**

### 为什么以前做不到？小米用了什么“黑科技”？

如果把大模型想象成一个参加考试的学霸，过去行业里很多提升成绩的方法，本质上是：给学霸配更好的书桌、买更多的参考书。

但小米做的事情不一样，它是在不影响考试成绩的前提下，把考试流程整体优化了一遍。具体分为三层，环环相扣：

**第一件事：给学霸“减负”**

学霸备考时，会带很多参考资料。如果每本书都厚得像砖头，会占用大量空间，找资料自然很慢。小米采用了**FP4****量化技术****。**简单理解，就是把部分对精度不敏感的内容压缩存放，就像把厚厚的纸质资料缩印成更轻、更容易翻阅的口袋书，内容基本没变，但占用空间更小，学习和查找速度自然更快了。

**第二件事：先写草稿，再统一检查**

传统大模型生成内容时，更像一个特别谨慎的学霸。写一个字，检查一次。再写一个字。再检查一次。这样当然稳，但效率不高。小米采用了**DFlash****解码技术****，**就像学霸先写一整段，再一次性检查、修改，而不是一个字一个字地改，没问题直接采用，写错了再单独重写，最终结果依然准确，但效率大幅提高了。

**第三件事：减少考试过程中的等待时间**

考试时最浪费时间的是什么？不是思考，而是找笔、整理试卷、传试卷，大模型也是一样。很多时候 GPU 并不是一直在计算，它还会等待数据、等待计算、等待调度。**TileRT****推理系统**就像是一套高效的考场管理系统，负责把整个考试流程安排得更高效，减少等待时间。简单说：不是让学霸少思考，而是把更多时间用在专心答题上。

正是靠着以上全链路能力的优化表现，小米 MiMo 大模型的推理工程能力，已跻身全球第一梯队。

附：技术理论解释

- 当前业界在追求类似极致速度时，往往选择走专用硬件路线，例如基于 wafer-scale 或 SRAM 的定制芯片架构，通用性较差，模型更新、架构修改后，原有的芯片架构就无法使用，从成本和用户收益上来说性价比很低，只能存在于实验室。
- 而小米选择了在通用 GPU 上，通过模型-系统协同设计来实现更惊人的推理速度，其中：
- 模型侧针对通用硬件的带宽瓶颈，进行了 FP4量化，大幅缩减模型体积并减少访存开销；同时引入基于块级 masked 并行预测的高效推测解码 DFlash，大幅提升单次验证的 Token 接受长度。
- 系统侧必须完美适配算法的动态特性，为全新的量化和推测解码流程量身定制专项优化的编译引擎与计算核，为此，我们引入 TileRT 超低延迟推理 Kernel/ 系统。

**05**

### 怎么保证“快”的同时不变笨？

这是大家最关心的问题。因为很多时候：快和强，很难同时做到。最简单的提速方法是什么？让模型少算一点，但这样往往模型会变笨。

我们做的并不是让模型少思考，而是尽量减少无效消耗。前面提到的每一步提速，都有对应的“防笨”机制。FP4 量化主要压缩对精度不敏感的部分，DFlash 所有预测结果都要经过验证，TileRT 优化的是系统效率，本身不会改变模型答案。因此，UltraSpeed 模式依然保持了与原模型一样的能力表现。

如果继续用学霸考试打比方，那就是只缩印一般的教科书，其他重要资料依旧保持原样，不影响阅读（ FP4 量化）；学霸写完每段后，必须检查、修正，确保准确性（ DFlash ）；减少找笔、准备的时间，真正思考问题的过程不能省略（ TileRT 优化）。

附：理论解释

- FP4量化：只压对精度最不敏感的 MoE 专家模块、其余保持原精度,并用量化感知训练边压边补,做到体积大降而能力几乎无损；

- DFlash 投机解码：让小模型一次并行“抢答”一整块 token,再由大模型无损验证,猜对才采纳、猜错就打回,最终输出和原模型完全一致,只是把“逐字确认”变成“整块确认”；

- TileRT 推理系统的加入：用常驻内核和异构流水线,把微秒级运行下计算步骤之间的启动、等待、搬数据等“空隙”基本消灭,只榨硬件时间、不碰计算结果。
