基本上前沿模型挨个跑了一遍，结果是：没有一个模型能通吃所有场景。

## 一、腾讯 WorkBuddy 公开了内部选模型的方法

先说为什么要自己造评测。

市面上主流的编码评测有两个问题。一个是题目本身能在网上搜到答案，模型有可能是"背题"过关。另一个是有些厂商从自家用户会话里抽题，分布贴近实际，但闭源。外面的人看不到题，也没法审计有没有选题偏向。

WorkBuddy Bench 的做法是：从真实的代码提交记录、代码审查请求、安全漏洞出发，逆向改写成口语化需求。改写之后，拿任务描述去搜索引擎搜，搜不到原始出处。通过出题方式本身，防止模型背题。

WorkBuddy分了四条赛道，各管各的

代码（80 题）：丢进 Django、Flask、pytest 这些真实开源仓库，模型自己找文件、改代码，用隐藏的测试用例打分。任务不只是修 bug，修 bug 只占 10 道，剩下 70 道是做功能、写测试、搞算法、做数据分析。每道题还带角色：开发者、算法工程师、PM、QA、运维，五种说话方式，模拟真实同事发消息。

前端（70 题）：不是让模型吐一段网页代码就算过关。每道题都有一个"必须交付能跑的东西"的硬约束，评测时会有自动化评测去实际点按钮、检查交互能不能用、刷新之后数据还在不在。从零搭建只占一半，另一半是改已有页面、写回归测试、做格式转换。

办公（50 题）：模型面对的是一个混合文件工作区：表格、PDF、JSON、Markdown 都有。要读多个文件、产出交付物，评测不只看输出的文件对不对，还要检查关联文件有没有跟着更新、有没有引入副作用。

安全（60 题）：红蓝兼顾。38 道攻击方任务（审计真实漏洞、二进制利用、Web 攻击、AI Agent 安全评估）和 22 道防御方任务（恶意软件分析、安全运营告警分析）。全程用确定性程序打分，不用大模型当裁判，背后有五层反作弊机制。

论文公开了在办公场景下的模型成绩单

七个模型跑了四条赛道，用两套执行环境分别跑，出了八张成绩单。

第一，没有全能冠军。Claude Opus 4.8 在代码赛道领先，GPT-5.5 在办公赛道的一套环境下拿了最高分（86.05），HY-3 在另一套环境下的办公赛道拿了 82.08，GLM-5.2 在安全赛道两套环境下都是第一（76.32 / 80.86）。

第二，换一套执行环境排名就会变。代码赛道变动最大：GPT-5.5 和 GLM-5.2 在两套环境下的排名是反的。说明同一个模型搭不同的工具链，结果不一样。选模型不能光看分数，还得看你拿什么工具跑它。

第三，开源模型在安全赛道力压闭源。GLM-5.2 拿了 80.86，后面是 GPT-5.5 的 77.91 和 Claude Opus 4.8 的 65.87。

二、就在三天后，混元也公开了他们的方法

WorkBuddy Bench 测的是"给你一个代码仓库或者一个工作区，你能不能完成任务"。E-Bench 测的是另一件事：在一个有状态的产品环境里，你能不能通过多步工具调用把事办成。

混元的基准用三个腾讯产品造了一个平行世界

E-Bench 模拟了三个产品场景：王者荣耀（游戏社交、好友管理、组队匹配）、QQ 音乐（歌曲搜索、歌单管理、收藏操作）、腾讯会议（查员工、订会议室、排日程、建群聊）。

环境不是从线上扒的，是从头合成的。团队把每个产品的关系数据库结构建出来，按表之间的依赖关系顺序灌数据，灌完再跑一轮校验修补时序矛盾和统计错误。最终三个场景加在一起：41 张表、345 列、69 条外键约束、7.6 万行数据、1219 个实体（玩家、用户、员工）。

*[图片]*

任务怎么出的？一个强模型（Claude Opus 4.7）当"出题者"，可以直接用 SQL 查全库、执行代码。它探索数据库状态、挑选目标实体、执行操作、记录下数据库变更作为标准答案。然后三个强模型（GPT-5.5、Claude Opus 4.7、GLM-5.1）当验证者，独立验证任务的可解性。至少两个验证者通过才收录。

核心设计：出题者全知，解题者半盲

这是 E-Bench 最关键的设计，论文里叫"信息差 + 工具差"。

信息差：出题者能看到整个数据库，所以它能出"把我收藏里所有两年前发行的歌都删掉"这种任务。答案取决于数据库里实际有哪些歌符合条件。解题者看不到数据库，只能通过业务工具一步步查。这逼着模型必须做完整的信息收集再动手，不能从题目里猜答案。

工具差：出题者能执行代码，解题者只有业务级工具（搜歌、查日程、加好友这些）。没有循环、没有聚合函数、没有 SQL，想完成一个需要遍历全部收藏歌曲的任务，就得一条条调工具去查。

这也是为什么 E-Bench 多了一个变体：给解题者也开放代码执行能力，看"补上工具差"能提升多少。

11 个前沿模型跑下来的成绩

最强的 Kimi-K3 也只有 73.79%。最好的模型在将近四分之一的任务上做不对。

可靠性是真正的瓶颈。Kimi-K3 的 Pass@3 是 87.62%（三次里做对过一次），但 Pass³ 只有 58.82%（三次全做对）。做对一次是运气，连续做对三次才是真本事。目前没有一个模型的 Pass³ 超过 60%。

代码执行改变排名。给了代码执行能力之后，Opus-4.8 从 68.78% 跳到 81.11%，直接反超 Kimi-K3（77.61%）和 GPT-5.5（77.19%）。强代码能力的模型占了大便宜。Gemini-3.5-Flash 更夸张，从第 9 名冲到第 6 名，涨了 47%。

王者荣耀最难（平均 43.64%），QQ 音乐最简单（61.39%），腾讯会议居中（58.87%）。

看一个实际的例子感受一下难度。腾讯会议里有一道题：

```
"我是市场营销部渠道运营组的胡伟杰，在深圳鹏创大厦办公。突发渠道事件，要紧急拉一个跨部门对齐会。参会人包括我自己，再从我的渠道运营组里挑除我之外工龄最长的两位深圳在职正式员工，另外从产品与设计中心下面的视觉设计组挑工龄最长的那位深圳在职正式员工。一共四个人，我来当发起人和主持人。时间这本月 4 月 21 日周一到 4 月 25 日周五之间，每天 9 点到 18 点之间，按半小时为步进扫一下这四个人的日程，挑出大家共同空闲的最早一个连续 1 小时时段……"
```

后面还有一长段：订会议室、建日历、建群聊、设群描述。HY-3 用了 13 轮对话、94 次工具调用完成了全部 15 个数据库状态变更，一个没错。这种长链条的多步编排能力，是纯文本问答测不出来的。

做对了还不够，还得看花了多少钱。E-Bench 同时统计了每个模型完成任务的 API 成本。DeepSeek-V4-Pro 单任务成本 0.028 美元，准确率 47.7%；Kimi-K3 单任务成本 0.634 美元，准确率 73.8%。

写在最后：Agent 已经开始场景化选模型

两篇论文各有各的短板。

WorkBuddy Bench 的代码赛道以 Python 为主，跨语言覆盖有限。办公赛道不涉及 OCR 和 GUI 操作。Claude Opus 4.8 在代码赛道有一组用了修改过的指令配置，跟其他模型的跑法不完全一致。

E-Bench 的环境和任务都是合成的，跟真实上线产品的复杂度仍有差距。为了防止针对性训练，环境和任务不开源。目前只覆盖单个产品内的任务，没有跨产品的流程。

但这两篇论文最有价值的部分，其实是现在 Agent 已经开始场景化选模型。

随着模型不断发展，一定再有一个全能冠军，只有适合特定任务的模型，和一套可以证明自己选型对错的公开方法。
